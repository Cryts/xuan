# 「谜语人」在中文玩家语境里的实证

> 调研于 2026-09-20。源：B站专栏（最高产）、必应 RSS（低产）、gcores（JS 渲染抓不到）。
> 引文一律经 `api.bilibili.com/x/article/view` 原样取回，未改写。
> **本文件补上了本项目此前只有英文源的缺口** —— 我们做的是中文修仙游戏，
> 玩家抱怨的原话就是中文的，**英文设计文献答不了这个问题**。

## 一、最有用的一条：玩家自己说出了正确判据

《活侠传》争议里，一位玩家写的诊断（cv35565938）——**可以直接当设计原则引用**：

> 「这些问题需要你在游戏系统里面告诉玩家，直接大红文字告诉玩家，
> 或者剧情潜移默化告诉玩家都行。核心就是，**你需要明确玩家的预期，
> 让他预期得到的和他想要的一致**。」
>
> 「制作者想玩家一周目坏结局、二三周目好结局带来的感情冲击大，欲扬先抑；
> 玩家想一周目尽可能逆天改命，然后处处受限。**一路上都是负反馈**，
> 努力半天一周目坏结局心态爆炸。」

**注意它的落点不是"该不该剧透"，是「预期管理」** ——
与 Slay the Spire 的 Giovannetti「我完全不知道结果会是什么……这永远是游戏设计的彻底失败」
是同一件事的两种说法（一个从玩家口、一个从开发者口）。

## 二、品类常态（不是个例，是行业惯例）

调研把它归纳成五条，**每一条都能在本项目里对上号**：

1. **选项后果不预告，靠 SL / 读档试错** —— 大侠立志传攻略里"sl"是**不用解释的通用动词**
2. **触发条件多变量复合，游戏内一个都不显示** —— 活侠传某秘籍：`好感<4 且 心相≥35 且 性情≥60`
   *（本项目对应：剧本破局条件是差集——**这条我们做得比它好**，`unmetText()` 已经会告诉玩家还差什么）*
3. **社区把内容逆向工程成表格 / 数据库** —— 鬼谷八荒「全奇遇选择贴士，**内附表格**」
4. **数值不透明，靠 wiki / 解包 / 第三方工具补齐** ——
   活侠传攻略作者在正文里**主动推荐 mod**（"骰子大师……**能看到选项的具体数值加减**"）
5. **官方默认"攻略生态"填补信息缺口**

## 三、最刺眼的一例：玩家靠注入工具读内存

《活侠传》全流程攻略（cv37349594，5.1 万阅读）前言原文：

> 「推荐大家开骰子大师玩，roll点方便外加**能看到选项的具体数值加减**」

**这是"选项不告诉后果"的最直接后果** —— 玩家不是不想要那个信息，
是**被迫去游戏外面拿**。同文还有：

> 「很多事件**藏得极深，不看攻略不可能触发**」
> 「事件触发的月份仅供参考 **实际触发需要满足前置条件**」（而正文里并没有给出前置条件）

## 四、反向案例：留白什么时候成立（唯一一篇高质量中文设计文）

《忆蚀》——游戏引导带来的玩家分歧（cv47948899）。它把两派立场并列：

- **大众派**：「游戏是服务玩家的……**引导不足属于游戏的设计缺陷**」
- **高玩派**：「弱引导**并非无引导**，而是把线索藏进场景、旁白与音效里……
  用场景构图、光影明暗替代显性提示」

**它有条件地把留白判为加分**，而那个条件是关键：

> 「弱引导不是刁难玩家，而是让恐怖回归**"未知与探索"的本质**」

——**留白成立的前提，是它服务于"未知与探索"这一核心体验。**
它还给了个可用的量化参照：「游戏的整体难度应该**略高于玩家的平均水平 5%-7%**」。

## 五、对本项目的直接结论

**《玄》要的是"未知与探索"，还是"构筑与决策"？**

- 如果是前者（悬疑、怪谈、灰雾之秘那一类），**留白是资产**
- 如果是后者（修为分布、破局条件、资源取舍），**留白是负债**

本作两者都有，所以正确做法**不是一刀切**，而是按内容分：
- **剧本破局** = 决策 → 给足信息（`unmetText` 已经做对，继续）
- **事件后果** = 决策 → 给方向与量级（`previewFor` 已做）
- **世界观与氛围** = 探索 → 留白（`m_outer_god` / `m_forbidden_knowledge` 那一类）

**同一条内容不该两头都占。** 把"氛围留白"用在本该给信息的地方，
就是活侠传那条 90% 好评却让玩家开 mod 的路。

## 六、没查到的（不许替它编）

1. **没有**任何官方补丁公告原文写明"增加了引导/提示/后果预览" —— 全是攻略作者的转述
   （`store.steampowered.com` 与 `steamcommunity.com` 均不可达）
2. **没有**开发者公开解释"为什么不告诉玩家后果"的原文。
   玩家普遍归因为"鸟熊喜欢藏东西"（cv36132940），**但没有开发者自述证实这是有意设计**
3. **贴吧 403 不可达**（curl + UA 均失败）；**gcores 搜索页是 JS 渲染的空壳**
4. 除《忆蚀》外，**没查到**第二篇以"信息缺失 vs 神秘感的界限"为议题的中文文章

## 七、一条值得单独记的张力

同一个特性，攻略作者与普通玩家的表述**相反**：

- 攻略作者：「事件藏得极深，不看攻略不可能触发」——**当褒义写**
- 普通玩家：「不看攻略根本玩不下去」

**说明"留白"的评价高度依赖玩家投入度，而不是设计本身。**
对本项目的含义：不能只服务高投入玩家，也不能只服务路过的人 ——
**这正是"难度略高于玩家平均水平 5%-7%"那条量化建议的用处。**

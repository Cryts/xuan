# 《玄》文字修仙 · 网页版设计规格（v1）

> 版本：v1.0 · 日期：2026-09-20 · 状态：设计冻结，可实施
> 上游依据：`文字修仙小游戏_总体设计方案.md`、`附录A_资源库Schema与样例.md`、`research_novels.md`、`research_opensource.md`
> 本文件是实施期的**唯一契约**。上游文档中与本文件冲突处，以本文件为准。

## 0. 一句话

**《玄》是一款「自由度为核」的可切换修炼体系文字修仙 Roguelike**：抽命格、选体系、走一世，在散事件中活着，在**封闭剧本**中靠理解规则破局，在**天机榜**上狩猎其他位面的天命之子——一局 5–8 分钟，一世一重开。

**核心卖点 = 自由度。** 其余一切设计服从于此。第 2 章是自由度的定义与度量，任何新增功能必须回答"它增加了哪一类自由度"。

## 1. 已冻结的决策

| # | 决策 | 取舍理由 |
|---|---|---|
| 1 | **部署到 GitHub Pages**（纯静态，无后端） | 零运维、零成本、可公开访问；牺牲服务端权威 RNG |
| 2 | **RNG 用确定性种子** `seed = hash(run_id, node_index, nonce)` | 无服务端时，确定性换来**可复现可回放**，这比"防作弊"对本作更重要——它让平衡模拟与 bug 复现成为可能 |
| 3 | **文本三层 L0/L1/L2 全静态 + L3 可选实时** | L2 预生成池是真 AIGC（构建期由子 agent 批量生成并审核）；L3 由玩家自填 API Key 直连 |
| 4 | **首发 6 体系包 + 32 母题 + 400+ 事件 + 60+ 结局** | 支撑"多局不重样"与"体系可切换"两个卖点 |
| 5 | **创新模块：天机榜 + 位面之子并行人生** | 详见第 6 章 |
| 6 | **不做自由文本输入** | 玩家输入永远是离散 ID（选项 / 物品 / 条件组）。守住零注入、零审核压力的安全底线 |

## 2. 自由度的七根支柱（核心章节）

> 用户明确指示：**自由度是《玄》的核心卖点**。本章定义自由度由什么构成、如何度量、如何不被功能侵蚀。

| # | 支柱 | 机制载体 | 度量 |
|---|---|---|---|
| 1 | **体系自由** | 6 个 World Pack 热切换，资产按 power_index 折算迁移 | 跨包存档迁移成功率 100% |
| 2 | **构筑自由** | 出身 12×3 · 天赋 ≥80 · 缺陷 ≥20 · 隐藏命格 ≥15 · 词条组合 | build 多样性指数 ≥0.65 |
| 3 | **抉择自由** | 每个事件 ≥1 个长期变量被改写，选项非线性排列 | 选项分布均匀度；无支配性策略 |
| 4 | **破局自由** | **多条件破局**：同一剧本 3–6 组破局条件组，达成哪一组决定结局 | 每剧本 ≥3 条独立通路；通路间互不包含 |
| 5 | **顺序自由** | 事件调度器加权抽样 + followup 窗口，允许多种推进顺序 | 同一 run 的节点序列熵 |
| 6 | **跨界自由** | 位面之子命运线可干预；其体系规则可**论道习得**并装到自己身上 | 可习得规则的跨包组合数 |
| 7 | **文本自由** | L1 变量槽 + L2 预生成池按 `(evt, band, pack, realm, state)` 寻址 | 文本命中唯一率；30 节点内不重复 |

### 2.1 设计检查表（内容生产完成后逐条自查）

任何事件/剧本在入库前必须通过：

1. 它是否至少改写了**一个长期变量**？（资源/债务/暴露/污染/因果/关系/flag）
2. 它是否存在**支配性选项**？（某选项在收益与风险上全面优于其他）
3. 高风险是否**不是唯一优解**？（稳健路线必须更慢但可控）
4. 同一母题在**不同体系包**下风险类型是否不同？
5. 剧本是否有 **≥3 条互不包含**的破局通路？
6. 破局条件组是否使用了 **≥3 种不同条件类型**？（避免全是道具检查）
7. 未破局是否**也是一种有内容的结果**（而非"操作无效"）？
8. 是否引入新的**长期变量**而未在状态层登记？

### 2.2 反模式（禁止）

- **伪选择**：选项文案不同但结算相同。
- **线性收益**：四个选项是收益 10/20/30/40 的排列。
- **单一破局**：剧本只有一条通路（这会把剧本退化成"解谜题"而非"选择题"）。
- **条件同质**：某剧本的破局条件全是 `items_any`。
- **自由文本输入**：任何形式的玩家自由输入框（含"给道号命名"——该功能走白名单词库组合，不让玩家打字）。

## 3. 三层事件结构

```
一世 = 20–30 节点
├── 散事件  (~70%)  单节点 · 1–4 选项 · 母题驱动 · 负责节奏与资源流动
├── 剧本    (~25%)  3–8 节点封闭世界 · 明规则+隐规则 · 多条件破局 · 负责智性峰值
└── 跨界剧本 (~5%)  位面之子主导 · 对方体系规则即隐规则 · 负责融合创新
```

### 4.1 剧本 Schema

```jsonc

  "kind": "scenario",
```

### 4.2 多条件破局（取代被否定的单一「以物破局」）

**设计原则**：剧本不预设解法，只预设**破局条件组**。玩家用哪一组破局，决定走向哪个结局。条件组之间**互不包含**，且必须使用**多种条件类型**。

```jsonc
"破局条件组": [
  {
    "id": "solve_light", "name": "解明",
    "conditions": [                                    // 全部满足
      { "type": "known_rule",  "ref": "rule_literal" },
      { "type": "affordance",  "ref": "镇魂" }
    ],
    "cost": "低", "outcome": { "ref": "end_tomb_light", "narrative": "scn_tomb.light" }
  },
  {
    "id": "solve_force", "name": "力破",
    "conditions": [
      { "any": [                                       // OR 组合，制造额外通路
        { "type": "attr",        "key": "root", "op": ">=", "value": 80 },
        { "type": "affix_count", "ref": "破甲", "count": 2 }
      ]}
    ],
    "cost": "高（重伤）", "outcome": { "ref": "end_tomb_force", "narrative": "scn_tomb.force" }
  },
  {
    "id": "solve_sacrifice", "name": "献祭",
    "conditions": [
      { "type": "relation", "kind": "道侣", "exists": true },
      { "type": "flag",     "ref": "willing_to_pay" }
    ],
    "cost": "失去道侣", "outcome": { "ref": "end_tomb_sacrifice", "narrative": "scn_tomb.sacrifice" }
  },
  {
    "id": "solve_bargain", "name": "交易",
    "conditions": [
      { "type": "learned_rule", "pack": "mystery", "ref": "rule_playacting" },
      { "type": "attr",         "key": "charm", "op": ">=", "value": 60 }
    ],
    "cost": "欠下因果", "outcome": { "ref": "end_tomb_bargain", "narrative": "scn_tomb.bargain" }
  },
  {
    "id": "solve_both", "name": "兼得",              // 组合触发隐藏结局
    "conditions": [
      { "type": "solved_any_of", "refs": ["solve_light", "solve_bargain"] },
      { "type": "attr", "key": "wits", "op": ">=", "value": 90 }
    ],
    "cost": "极低", "hidden": true,
    "outcome": { "ref": "end_tomb_both", "narrative": "scn_tomb.both" }
  }
]
```

**条件类型全表**：

| type | 参数 | 含义 | 自由度作用 |
|---|---|---|---|
| `attr` | key, op, value | 六维属性门槛 | 构筑自由 |
| `var` | key, op, value | 长期变量门槛（debt/karma/corruption/exposure） | 抉择自由 |
| `item` | ref, count | 持有指定物品 | 资源自由 |
| `affordance` | ref, count | 持有带指定**功能标签**的任意物品 | **涌现**：新物品自动成为解法 |
| `affix_count` | ref, count | 词条数量 | 构筑自由 |
| `known_rule` | ref | 已揭示某条隐规则 | **理解即钥匙** |
| `learned_rule` | pack, ref | 已习得某体系的规则 | 跨界自由 |
| `flag` | ref | 布尔标记 | 抉择自由 |
| `relation` | kind, exists/delta | 关系（道侣/师徒/仇家/护道人） | 关系自由 |
| `faction_tier` | ref, op, value | 阵营声望 | 阵营自由 |
| `solved_any_of` | refs[] | 已完成的其他条件组 | **组合涌现** |
| `node_count` | op, value | 已在此剧本中消耗的节点数 | 节奏压力 |
| `any` / `all` / `not` | 子条件 | 逻辑组合 | **组合爆炸即自由度** |

**为什么这比"以物破局"自由得多**：`affordance` 只是 13 种条件类型之一，且可与 `any`/`all`/`not` 任意嵌套。玩家不是在"检查背包"，而是在**用属性、知识、关系、因果、已习得的跨体系规则，组合出一条破局路径**。设计师写条件，不写解法。

### 4.3 剧本推进

剧本占用 `span` 个连续节点。每个节点：
- 展示当前**已揭示**的明规则与隐规则（未揭示的显示为「未解」，给玩家推理动机）
- 提供 1–4 个常规选项（推进用）
- **恒提供一个「以物/以法试之」入口**：从背包或已习得规则中选择一项尝试，走 affordance / learned_rule 匹配
- 每次尝试推进一刻（时间压力），失败也有叙事内容
- 达成任一破局条件组即跳出剧本，结算对应结局线索

**时间压力**：`node_count` 条件类型让"耗到刻满"成为真实威胁——玩家必须在信息不足时决定是否冒险尝试。

## 5. 相性系统（跨体系对抗的地基）

每个体系包声明其**本体**——power 究竟是什么：

| 包 ID | 原创名 | 本体 | 玩法原型 |
|---|---|---|---|
| `mortal` | 青冥仙途 | **气** | 慢热经营 |
| `genius` | 炎武纪元 | **气** | 热血升级 |
| `physique` | 太古遗蜕 | **体** | 高强度成长 |
| `mystery` | 灰雾之秘 | **灵** | 解谜扮演 |
| `rebel` | 逆天问道 | **意** | 长线杀伐 |
| `cautious` | 苟道长生 | **势** | 低风险求生 |

**相克环**（每条边有小说逻辑支撑）：

```
气 克 体    灵气可淬炼、亦可侵蚀肉身
体 克 灵    以力破巧，蛮力冲垮精神
灵 克 则    认知可以理解、污染、扭曲规则
则 克 意    天地规则碾压逆天意志
意 克 气    意志强行催动、打散能量
势 ——不入环：不克人、不被克，但极难被杀（替身/后手）
```

克制方判定 **+30%**，被克方 **−30%**。玩家可学习并针对。

## 6. 位面之子（创新模块）

每局 seed 时从**其他体系包**生成 0–3 个位面之子。他们在后台走自己的命运线，**会真的变强**。

### 6.1 原型轴（拒绝"都是爽文主角"）

| 原型 | 行为 | 破法 |
|---|---|---|
| 蛮力型 | 数值成长最快 | 正面打不过，只能借规则杀 |
| **智谋型** | 成长慢，但**会读你的牌**——针对你的构筑调整自己 | 必须在他读懂你之前动手 |
| 苟道型 | 气运池极深，难杀 | 别杀，结盟——他会成为最强护道人 |
| 反套路型 | "金手指"其实是诅咒，命运线终点是自我毁灭 | 帮他，或抢在诅咒发作前夺取 |
| 悲剧型 | 命运线注定失败，且失败会波及你 | 改变他的命运线——本作最难成就 |

**智谋型的反制机制**：他记录你对他用过的手段（`used_against[]`），下次出现时携带对应抗性。这让"磨主角光环"从体力活变成**信息博弈**：你是否愿意现在暴露手段。

### 6.2 气运护体（主角不死性 = 可耗尽的资源）

- 每个位面之子有 `destiny_pool`（气运池）。
- 你对他造成致命结果时，**不直接结算**，而是触发「天意庇佑」检定。通过则给出一个**合理的巧合**救走他（护道人及时赶到 / 天雷劈偏杀招 / 你的仇家恰在此刻杀来）。
- **每次庇佑扣除气运池**。池子见底后巧合再也编不出来——**他就真的会死**。

设计价值：同时解释"主角为什么不死"与"你为什么终究能杀死主角"；把主角光环变成**可规划的长线狩猎目标**。

### 6.3 天机榜（常驻 UI）

实时展示每个位面之子：姓名 / 出身体系 / 当前战力 / **气运余量** / 命运线进度 / 所在区域 / 对你的关系 / 一句谶语式「天机批注」。
玩家的核心决策依据：看着气运条被一点点磨掉，决定何时下手。

### 6.4 命运线推进

每个位面之子生成时从其体系的母题中抽 3–5 个里程碑组成命运线（如 `被退婚立誓 → 残魂导师 → 异火融合 → 宗门大比夺魁 → 成神`）。玩家每推进一个节点，他们也推进一次（各用各的种子）。其命运线会**反馈到世界**：提升区域危险度、开启/关闭事件、衍生针对玩家的事件。

### 6.5 论道与跨界习得

相遇剧本的 `论道` 通路可产出 `learn_rule` 效果。**玩家因此在自己身上装了一套外来体系规则**——例如凡人流的你习得 `mystery` 的扮演法，角色从此长出一个 `sanity` 槽。

这是"体系融合"的落地：不是文案，是**真的往状态层加规则**。习得规则同时是第 4.2 节 `learned_rule` 条件类型的数据来源——**跨界习得直接打开新的破局通路**。两条系统在此咬合。

## 7. 文本层与 AIGC

| 层 | 内容 | 来源 | 占比目标 |
|---|---|---|---|
| L0 | 规则文本、提示、失败语 | 手写 | 30% |
| L1 | 变量槽组合模板 | 手写模板 + 运行时变量填充 | 45% |
| **L2** | **预生成候选文本池** | **构建期由子 agent 批量生成 + 审核入库** | **24%** |
| L3 | 结局卷轴、罕见奇遇、道号生成 | 玩家自填 API Key 实时调用（可选） | 1% |

**L2 是本作的 AIGC 体现**。寻址键：
```
key = hash(evt_id, band, pack, realm_bucket, dominant_attr, mood_hint)
```
每个 key 预生成 2–4 个候选，带**轻度扰动**（同义替换一个变量）避免重复感；玩家级去重：同一玩家 30 节点内不重复同一文本。

**合规红利**：因 L0–L2 全部构建期确定，本作**不产生实时 AI 生成内容**。L3 由玩家自带密钥、内容直连模型不落我方服务器。设置页保留「AI 生成」标识说明，满足《人工智能生成合成内容标识办法》（2025-09-01 施行）的告知义务。

**L3 安全边界**：玩家 Key 存 `localStorage`，仅存本地；调用前显式告知风险；输出经前端数值剥离器（正则）清洗后才渲染；失败静默降级到 L2。

## 8. IP 与内容安全

| 层 | 机制 | 强度 |
|---|---|---|
| 构建期硬门禁 | 禁用词表（原著专名/角色/组织/招式，≥300 词），命中即 **build fail** | 不可绕过 |
| 撞名检测 | 生成姓名/地名/宗派/法宝对原著名单做相似度 + 谐音检测 | 不可绕过 |
| 风格致谢分离 | 每包带 `inspiration_tag`（如"凡人流·慢热经营"），**只致谢风格结构，不含独创表达** | 结构性隔离 |
| 原创性报告 | 发布前输出高辨识度名词全清单，人工过审 | 人工门禁 |
| 运行时 | L0–L2 全构建期确定，无实时 AIGC 内容面 | 天然合规 |

**原则**：借鉴「规则与结构」，不使用「独创表达」。通用修真词（炼气/筑基/金丹/元婴/化神/天劫/秘境/丹药/灵石/法宝/妖兽/宗门）可保留；作品独有名词 100% 替换。

## 9. 技术架构

```
xuan/
├── packages/
│   ├── game-core/          # 纯 TS：零 DOM / 零浏览器 API / 可在 Node 跑模拟
│   │   ├── engine/         #   状态机 · 事件调度器 · 种子 RNG · 剧本推进器
│   │   ├── rules/          #   结算 · 突破 · 相性 · 破局条件求值 · 命运线推进
│   │   ├── schema/         #   Zod 契约
│   │   └── save/           #   快照 + 事件流
│   └── content/            # 版本化 JSON 资源库
├── app/                    # React 19 + Vite + TS 视图层
├── tools/                  # content-lint · 蒙特卡洛模拟 · 原创性报告
└── docs/
```

**关键约束**：`game-core` 不 import 任何浏览器 API。同一套代码既跑游戏，也在 Node 跑 10 万局蒙特卡洛。

**渲染**：水墨国风，暗色为主。主色 墨黑 `#12100E` / 宣纸 `#F2EAD9` / 朱砂 `#C1392B` / 青碧 `#3E7C6E` / 鎏金 `#C9A227`。动效全部 CSS 关键帧，可关闭，respect `prefers-reduced-motion`。
